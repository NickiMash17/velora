# Company

**Status:** Active — [ProductPrinciples.md](./ProductPrinciples.md) written; the rest below is still placeholder.

This folder holds non-technical, company-level documentation: mission, vision, values, org structure, and internal policies that apply regardless of what's being built. It is intentionally separate from `product/` (what we're building) and `pitch/` (how we present it externally).

## Contents

- [`ProductPrinciples.md`](./ProductPrinciples.md) — the seven founding principles every feature and design decision is checked against (the "Employee Test," explainability, humans-manage/AI-executes, trust-over-autonomy, and more), each grounded in where it's already enforced in `architecture/` and `product/`, with gaps flagged rather than assumed covered.

## Expected contents (not yet written)

- `Mission.md` — why Velora exists
- `Vision.md` — where Velora is going
- `Values.md` — how we make decisions and treat each other
- `OrgStructure.md` — team structure, roles, ownership boundaries as the company grows

Founders / Leadership. Engineering should treat this folder as read-only context, not a place to make architectural decisions.
